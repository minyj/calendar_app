모델 역량 천장 — 게이트가 못 올림

1 · 게이트 깔때기 — 14건이 어디서 걸리나 (싼 게이트 → 비싼 게이트)

대부분 G0~G3(형식·문법·범위)의 값싼 정적 검사에서 걸린다. 테스트(G4)까지 도달해 HITL로 회부되는 건 3건뿐. AUTO_APPLY(초록)는 0 — 30B는 안전하게 자동적용할 수준의 패치를 아직 못 만든다.

2 · H1 vs H2 — 실패 유형이 이동한다 (게이트는 둘 다 잡는다)

H1 기본은 문법파손·파괴적삭제(SYNTAX/SCOPE)가 주류, H2 검증강제는 프롬프트 압박에 형식붕괴(FORMAT: 산문/조각)로 실패가 이동. 하네스 프롬프트가 실패모드를 바꿔도 게이트 레이어는 두 실패군을 모두 차단한다.

3 · 게이트 유무 (같은 데이터, 다른 결과)

게이트 없음: 에이전트가 "완료"라 한 12건을 그대로 신뢰 → 전부 불량(4건은 코드 파손). 게이트 있음: 위험 자동적용 0 · 위험 100% 차단 · 애매한 것만 사람에게.

4 · 인스턴스별 판정

데이터: runs/*/preds.json + logs/run_evaluation/*/report.json + test_output.txt(SyntaxError 계측). gold 채점 resolved=True 로 파이프라인 정상 확인 → 0 resolved 는 하네스 버그가 아닌 모델 역량 결과. 판정 규칙: 전부통과=AUTO_APPLY · G0–G3통과·테스트실패=HITL · G0–G3실패=REJECT.
